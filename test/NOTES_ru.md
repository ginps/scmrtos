### Исправления порта Linux

- **Приоритет переключения контекста.** Сигнал переключения был `SIGUSR1` и доставлялся раньше остальных ожидающих. Теперь это `SIGRTMIN+8`, он обрабатывается последним, как PendSV. Добавлен бит «ожидает», чтобы запрос не дублировался.
- **Вход в новый процесс.** Процесс стартует с запрещёнными прерываниями и разрешает их сам (`process_entry`): `swapcontext()` ставит маску сигналов раньше переключения регистров.
- **ASan:** порт снимает «отравление» стека при (пере)запуске процесса.
- **Новое API:** `get_interrupt_state()`, макрос `scmRTOS_LINUX_CRITSECT_EXIT_HOOK`.
- **Проверка:** перезапуск процесса вне критической секции завершает программу с сообщением.

### Найденное

- **Пробел в тестах закрыт.** Откат upstream‑исправления `aa4e99d` (потерянное пробуждение в схеме 1) не замечал ни один тест. Причина была в приоритете сигнала в порте. Теперь откат ловят `kernel.isr_signal_arriving_while_the_waiter_blocks` и `kernel.timeout_expiring_while_the_process_blocks`.
- **Дефект 1 подтверждён на настоящих 16‑битных целях** (msp430, avr): 12 проверок из 28 не проходят на develop и v5.2.0, с патчем 0001 проходят все 28.
- **N7 (новый).** `force_wake_up()` процесса, ждущего в `TMutex::lock()` или `channel::push()`, оставляет его метку в карте ожидания сервиса. Следующий `unlock()`/`pop()` «будит» этот процесс из постороннего `sleep()`.
- **N8 (новый).** `round_robin_mgr`: флаг `put_off[0]` первого зарегистрированного процесса остаётся `true` с конструктора, и менеджер будит этот процесс из его собственного `sleep()`.
- **N9 (новый, мелкий).** `os_running()` из глобального конструктора, выполненного раньше конструктора `OS::Kernel`, возвращает `true`. Проверено GCC `-O0`/`-O2` и Clang `-O2`.
- **Дефект 2 находится автоматически.** На v5.2.0 его воспроизводят все режимы фаззинга, включая одиночное прерывание (например, seed 34).

## 3. Выжившие мутанты: итоговый разбор (45)

| Группа | Число | Примеры | Вывод |
| --- | --- | --- | --- |
| Эквивалентные | 16 | `cnt <= Count` → `<` в `min`, `DUMMY_INSTR()`, повторное `Timeout = 0`, `NestCount` после `force_unlock`, условия `safe_run` | исключены из знаменателя |
| Критические секции в `*_isr` | 9 | `signal_isr`, `unlock_isr`, `send_isr`, `write_isr`, `set_isr`, `release_isr` | в порте обработчики не вкладываются; исключены |
| Чтение одного слова | 2 | `is_sleeping`, `is_suspended` | атомарно на x86‑64; исключены |
| Особенность порта | 1 | сохранение `StackPointer` в `context_switch_hook` | исключён |
| Скрыты известным дефектом | 7 | тело `try_pop_back` (N1), `put_off` в round‑robin (N8) | погибнут после исправления дефектов |
| Окна гонок без точки подачи прерывания | 5 | `TRecursiveMutex::try_lock()`, снимок профайлера, `alive/asleep` watchdog | нужен пошаговый перебор по инструкциям |
| Защитные остановки | 4 | `launch_precheck`, проверки порчи таймаута в watchdog | недостижимы через API |

Предположения предварительного разбора проверены: критические секции в функциях процесса и канала убивает проверка в хуке переключения и тесты с `TGuarded`; «чтение‑изменение‑запись» в `TEventFlags`/`TSemaphore` — набор `atomic`; `(1ul >> PROCESS_COUNT) - 1` — программа на 8 процессов; выход за массив в профайлере — ASan.

## 4. Возможные следующие уровни глубины

| Уровень | Что даст | Реализуемость здесь |
| --- | --- | --- |
| Пошаговый перебор по инструкциям (флаг трассировки x86, `SIGTRAP`) | доказательство атомарности каждого вызова; убьёт оставшиеся мутанты критических секций | да, 1–2 дня работы |
| Перебор пар прерываний в сценарии (граница вытеснений 2) | все размещения двух прерываний: ≈1,9 млн запусков, около 25 минут | да, это параметр существующего теста |
| Покрытие MC/DC (clang `-fcoverage-mcdc`) | условие/решение вместо ветвей | да, clang 18 есть |
| Фаззинг последовательностей API с обратной связью по покрытию (libFuzzer) | находит сценарии, которые не придумал человек | вероятно да, нужна адаптация запуска без `fork` |
| Статический анализ (clang-tidy, clang analyzer) | дефекты без запуска | да |
| Исполнение настоящих портов в эмуляторе (QEMU для Cortex‑M, simavr) | проверка ассемблерного переключения контекста и обёрток прерываний — того, что хост‑тесты не видят в принципе | нет: нужны кросс‑компиляторы, сеть в сессии отключена |
| Замеры времени: задержка прерываний, длина критических секций | свойства реального времени | только на железе или в потактовом эмуляторе |

## 5. Как продолжить

```sh
cd scmrtos                       # develop @ 5b8f67f
git am patches/*.patch
test/unit/run.sh                 # вся матрица, ≈2 минуты
test/target16/run.sh             # нужен clang с целями msp430 и avr

# мутационное тестирование
test/unit/coverage.sh --dump-covered=/tmp/covered.txt
python3 test/unit/mutate.py --covered /tmp/covered.txt --work /tmp/mut --fuzz-seeds 30 --report /tmp/mut.txt
python3 test/unit/mutate.py --covered /tmp/covered.txt --work /tmp/mut --retest /tmp/mut.txt.json \
        --cxxflags "-fsanitize=address,undefined -fno-sanitize-recover=undefined" --report /tmp/mut-san.txt
```

Следующий по отдаче шаг — пошаговый перебор по инструкциям из раздела 4: он закроет 5 мутантов из группы «окна гонок».
